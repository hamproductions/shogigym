# 駒描画のインスタンシングと大局将棋の平面化

更新日: 2026-10-08。ローカル開発版で検証。未コミット・未デプロイ。

## 適用範囲

| 最適化                                           | 通常将棋               | 大局将棋 |
| ------------------------------------------------ | ---------------------- | -------- |
| InstancedMeshによる駒の一括描画                  | 有効                   | 有効     |
| テクスチャ配列による木目・文字・仕上げの個別指定 | 有効                   | 有効     |
| 彫刻をなくした共通の平面形状                     | 無効。従来の彫刻を維持 | 有効     |

通常将棋で彫刻をなくす変更は実施していない。大局将棋では本体、駒の寸法、文字、木目、塗膜、光沢の設定を維持し、表面の凹凸と凹凸用法線マップを省略する。共通の駒生成経路を利用するため、大局将棋の3D盤面、捕獲駒、焼き込み2D表示に適用される。2Dの実行時速度は測定していない。

## 実装

- `src/rendering/board3d/instances.ts`: 形状、材質設定、影、描画順、レイヤー設定が一致するMeshを一括描画する。通常将棋では元のオブジェクトを保持して当たり判定・アニメーションに使用し、描画時のみ非表示にして終了後に復元する。
- `src/rendering/board3d/instanceTextures.ts`: 元のCanvasTextureまたはRGBA unsigned-byte DataTextureをDataArrayTextureに格納する。map、emissiveMap、roughnessMap、clearcoatMapごとにInstancedBufferAttributeでスライスを指定する。標準の物理材質のシェーダーを部分変更し、照明や仕上げを維持する。
- 配列化には寸法、色空間、サンプリング、UV変換が一致することが必要。各スロット128層を上限にバッチを分割する。透明・透過材質や独自描画フックは通常のMesh描画へ戻す。すべての仕上げが同じバッチ数になる保証はない。
- `src/features/taikyoku/pieces.ts`: CustomFaceのreliefをfalseにして平面形状を選ぶ。
- `src/features/taikyoku/scene3d.ts`と`captures.ts`: 盤面と静止した捕獲駒でテクスチャ配列を有効にする。移動中・持ち上げ中の駒は元のMeshを使用し、終了後にバッチへ戻す。

## 測定条件

実際のheaded Chromium、Apple M2 ProのANGLE Metal GPU、localhost:5173。描画バッファ1152×471、DPR1。同じ局面・カメラで比較。GPU時間はEXT_disjoint_timer_query_webgl2を使用し、GPU disjoint=falseを確認した。各窓70フレームの最初10フレームを除外し、中央値を記録する。影の更新を強制した追加描画を測定しているため、値は通常ループ全体の時間やFPSではない。CPU値には描画の呼び出しと、通常将棋ではバッチ更新を含む。CPUとGPUは並行するため、単純加算しない。

## 実際の操作後の結果

### 通常将棋

検討画面でポインター操作により7七→7六歩、3三→3四歩、8八→2二角の捕獲、成る選択を実施。棋譜の3手目、龍馬、持ち駒の角、アニメーション終了を確認し、画面を直接確認した。

同じ局面で通常Mesh描画と現在のインスタンシングを交互に各2窓測定した。

| 指標               | 通常Mesh              | インスタンシング      |
| ------------------ | --------------------- | --------------------- |
| 総draw call        | 305 / 306             | 108 / 106             |
| CPU中央値          | 1.750 / 2.095ms       | 1.310 / 1.135ms       |
| GPU中央値          | 1.172083 / 1.203208ms | 1.251874 / 1.343500ms |
| 影を含む総三角形数 | 112244 / 113316       | 113316 / 112020       |

各窓の中央値を平均して比較すると、draw callは64.98%削減、CPUは36.41%削減。GPUは9.27%増加しており、インスタンシングによるGPU高速化は実証していない。動作中のアバターなどにより総三角形数が窓間で変わるため、これは実行中の場面の比較であり、完全に固定された全シーンの比較ではない。各窓60件の有効GPU結果を取得した。

### 大局将棋

18十一の歩兵をポインターで選択し、持ち上げと移動先を確認して18十二へ移動。実際のエンジンが19三十三→19三の大将で応答した。盤面788駒、捕獲16駒、先手393・後手395、アニメーション終了、捕獲駒の3バッチを確認した。捕獲箱の表示を直接確認し、ブラウザーエラーはなかった。

操作後の同じ局面で盤面の完全一致材質バッチとテクスチャ配列バッチを交互に各2窓測定した。捕獲駒は両条件とも配列化したままなので、以下は盤面バッチ変更の差を表す。

| 指標               | 完全一致材質バッチ    | テクスチャ配列バッチ  |
| ------------------ | --------------------- | --------------------- |
| 盤面バッチ数       | 230 / 230             | 16 / 16               |
| 総draw call        | 634 / 634             | 206 / 206             |
| CPU中央値          | 2.730 / 2.600ms       | 1.305 / 1.200ms       |
| GPU中央値          | 0.815833 / 0.933374ms | 0.884125 / 0.863541ms |
| 影を含む総三角形数 | 101807 / 101807       | 101807 / 101807       |

各窓の中央値を平均して比較すると、draw callは67.51%削減、CPUは53.00%削減。GPU平均は0.874604ms対0.873833msでほぼ同じ。各窓60件の有効GPU結果、disjoint=false。選択・移動・エンジン応答・捕獲駒表示を通した動作は確認済みだが、全駒種・全仕上げ・全捕獲規則の網羅試験ではない。

## 表示の一致と制約

平面の大局将棋の配列化前後は同一場面の全2170368色チャンネルで差分0だった。通常将棋の初期局面では46チャンネルに微小差分があり、平均差0.0000705、最大22。完全一致とは扱わない。彫刻から平面への変更は凹凸を意図的に除去するため、表示の完全一致は目標ではない。

インスタンシングはdraw callとCPUの描画準備を減らす。今回の大局将棋では平面化による三角形削減が主要なGPU改善だった。60Hzで既に描画できる場合、これらの削減が同じ割合のFPS増加になるわけではない。iPad・モバイル、長時間利用、読み込み時間、VRAM使用量、焼き込み2Dの性能は未測定。

一時的な測定フックはソースから削除した。ローカル画面証拠はconductor/gains-normal.pngとconductor/gains-taikyoku.png。公開・コミット用の証拠としては扱わない。
